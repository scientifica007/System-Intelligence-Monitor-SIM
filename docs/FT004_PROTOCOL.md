# FT-004 — تجربة تأخر التسجيل والتلخيص في SIM v0.1.0a3

**الحالة:** بروتوكول اختبار ميداني **لم يُنفذ بعد**.  
**نظام الاختبار المرجعي:** Ubuntu 24.04.5 LTS، Intel i3 M370 (2C/4T)، 8 GB DDR3، Intel i915، قرص قديم.  
**المرجع:** [FT-003](FT003_FINAL.md) رصد 14 فجوة فوق 3 ثوانٍ وأطول فجوة حسب طابع UTC كانت 23.902 ثانية، رغم سلامة 1137 عينة.

## 1. الغاية والفرضية
تحديد إن كان تأخر العينات ناتجًا عن طول تنفيذ المجمّع، أو زمن الكتابة، أو انتظار الجدولة، دون نسبة سبب قبل وجود دليل. لا يضمن هذا الإصدار علاج كل فجوة: يضيف قياسًا وتسجيل أحداث وجدولة بمواعيد مطلقة وعدم محاولة «اللحاق» بعينات مفقودة. لا تُنشأ بيانات تعويضية وهمية.

## 2. التحضير والتحديث
```bash
cd ~/System-Intelligence-Monitor-SIM
.venv/bin/sim status --json
.venv/bin/sim stop --json
git pull --ff-only
.venv/bin/python -m pip install -e .
.venv/bin/sim --version    # SIM 0.1.0a3
.venv/bin/python -m pytest -q    # إذا كان pytest مثبّتًا في البيئة
```
`git pull --ff-only` لا يُفترض أن ينجح إذا كان لدى المستخدم تغييرات Git محلية متعارضة؛ في هذه الحالة لا تستخدم `git reset --hard`.

## 3. معايرة أولية للملفات القديمة — من دون تشغيل مسجل
```bash
.venv/bin/sim summary 20261028T204716Z-9381b675 --json > ~/sim-ft003-summary.json
.venv/bin/sim summary 20261028T194549Z-479a6b04 --json > ~/sim-ft001-summary.json
```
ينبغي أن يرى SIM **1137** عينة في FT-003 ونحو **14** فجوة تتجاوز 3 ثوانٍ، باحتساب `monotonic_ns`؛ القيمة القصوى قد تختلف قليلًا عن 23.902 ثانية المحسوبة من UTC. حقول توقيت المجمع الجديدة `null` في الإصدارات السابقة وهذا متوقع.

## 4. جلسة FT-004 — ثلاثة سيناريوهات مضبوطة
ابدأ الجلسة التالية (30 دقيقة على الأقل) مع بقاء الجهاز في وضع الطاقة نفسه:
```bash
.venv/bin/sim start --interval 2 --process-every 5 --process-limit 300 --max-session-mib 128 --label "FT-004 timing" --json
```
خلال الثلاثين دقيقة: **10 دقائق خمول نسبي** (لا تفتح برامج جديدة)، **10 دقائق Brave عمل اعتيادي**، **10 دقائق نشاط أعلى** (صفحات متعددة أو تشغيل برنامج ثقيل مألوف، *بلا* أدوات إجهاد حراري صناعية على العتاد القديم). دوّن وقت الانتقال بين الحالات بتوقيت الجهاز. لا تغيّر تردد المعالج يدويًا أو إعدادات الطاقة خلال التجربة.

يمكن أثناء العمل مراجعة:
```bash
.venv/bin/sim status --json
.venv/bin/sim show temperatures --json
.venv/bin/sim top --sort cpu --limit 15
```

بعد 30 دقيقة أو أكثر:
```bash
.venv/bin/sim stop --json
.venv/bin/sim sessions list --json
```
استخدم **المعرّف الفعلي** الذي ظهر في نتيجة `stop`، وليس النص التوضيحي `SESSION_ID`:

```bash
.venv/bin/sim summary SESSION_ID --json > ~/sim-ft004-summary.json
.venv/bin/sim export SESSION_ID --format jsonl --output ~/sim-ft004-20261028.jsonl
```
إذا كان ملف التصدير موجودًا من محاولة سابقة، اختر **اسمًا مختلفًا**؛ لا يحذف SIM الملفات ولا يستبدلها. يمكن استخراج سجل الأحداث من المسار الموجود في `~/.local/share/sim/sessions/SESSION_ID/events.jsonl`. لا ترفع تسجيلات العمليات الخام إلى مستودع عام.

## 5. بيانات مطلوبة من المستخدم
- مخرجات `sim --version` و`sim stop --json`.
- `sim-ft004-summary.json`، وملف `sim-ft004-20261028.jsonl` مع ملف `events.jsonl` المرتبط بالجلسة.
- أوقات بدء الفترات الثلاث وملاحظات أي توقف محسوس أو بطء.
- إن أمكن، قياس خارجي لكلفة SIM مقارنة بخط أساس من دون SIM قبل/بعد جلسة العمل، **وليس** استنتاجًا سببيًا من جلستين مختلفتي الحمل.

## 6. معايير القبول
- تطابق معرّفات الجلسة وعدد العينات الفعلية مع manifest، وصحة JSONL لكل سطر.
- تسجيل `collector_duration_ms` و`sampling_lateness_ms` لكل عينة و`previous_write_duration_ms` لكل عينة عدا الأولى.
- توافق عدد أحداث `sampling_delay` في `events.jsonl` مع `summary.gaps_over_threshold` للجلسة الجديدة إذا لم يحدث توقف فاشل أثناء كتابة الأحداث.
- عدم وجود عينات اصطناعية، وتوثيق `schedule_overrun` عند تجاوز مواعيد أخذ عينات.
- مقارنة عدد ومدة الفجوات مع FT-003، مع مراعاة اختلاف الأحمال. **الهدف** خفض أو تفسير الفجوات، ولا يُعلن PASS لانتظام مطلق قبل تحقق البيانات.
- عدم تجاوز عبء المراقب حدودًا غير مقبولة للجهاز؛ هذا يحتاج قياسًا مع مصدر خارجي.

## 7. معاني الحقول الجديدة
- `timing.collector_duration_ms`: الزمن الفعلي من بداية استدعاء `Collector.sample` إلى نهايته، شاملًا جمع العمليات والحرارة، لكنه لا يفصل تلك المجمعات بعد.
- `timing.sampling_lateness_ms`: مقدار تأخر بدء دورة الجمع عن موعد الجدولة المطلق بالساعة الرتيبة.
- `timing.previous_write_duration_ms`: زمن كتابة **العينة السابقة** مع `fsync` إذا نُفذ في تلك الدورة. الأولى `null`.
- `sampling_delay`: حدث حين يزيد الفارق الفعلي عن `max(3s, 1.5×interval)`.
- `schedule_overrun`: حدث عند تخطي موعد أو أكثر؛ لا تُنشأ سجلات مقابل المواعيد المتخطاة.
- `sim summary`: تحليل وصفي streaming من جلسة محفوظة، لا يحتاج إلى مسجل يعمل ولا يقدم سببًا آليًا للفجوات.

**قيود قائمة:** لا توجد بعد خدمة systemd --user، ولا ضغط/تدوير، ولا قياس GPU أو الطاقة لكل تطبيق، ولا ضمان استمرار بعد logout. ما زالت النسخة Alpha.
