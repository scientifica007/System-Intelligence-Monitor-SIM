# تقرير التنفيذ الأولي — SIM v0.1.0a1

**التاريخ:** 28/10/2026. **الحالة:** نموذج أولي منفذ، اختُبر في بيئة Linux معزولة، اجتاز أول اختبار ميداني قصير على جهاز Ubuntu 24.04 الخاص بالمستخدم (129 عينة في 4 دقائق و16 ثانية)، وتبقى اختبارات التحمل الطويل والمقارنة مستقلة مطلوبة. **لم تُصدر حزمة تثبيت .deb.**

## المنجز
- Python package قابلة للتثبيت بـ `pip install -e .` وأمر `sim`.
- `sim doctor`: جرد النظام وأنوية CPU والذاكرة وأجهزة DRM والقدرات المدعومة أو غير المدعومة؛ تصدير JSON.
- نواة `Collector`: CPU system/operations، RAM، Swap، disk/network rates، process RSS و CPU per core/machine، توقيت UTC وفواصل monotonic، معالجة غياب العدادات وتغير PID.
- مسجل خلفي مستقل عن الطرفية في الجلسة الحالية، يبدأ بـ `sim start` وينتهي بـ `sim stop`؛ `sim status` يعرض حالته دون تسريب token التحكم.
- جلسات محلية و`manifest.json` و`capabilities.json` و`samples.jsonl` و`events.jsonl`، مع تمكين `sim sessions list/show`.
- `sim show cpu/ram/disk/network/gpu/power`, `sim top`, `sim live`، وتصدير JSON/JSONL بدون استبدال الملفات الموجودة.
- اختبارات آلية لوحدات الحساب والتسجيل والإيقاف والتصدير، بالإضافة إلى سير عمل GitHub Actions على Ubuntu 24.04.

## غير المنجز بعد
- Desktop GTK، حزم .deb، SQLite، تحليل الاختناقات الذكي، مقارنات التجارب، توصيات، القياس الحقيقي لكل تطبيق على GPU والطاقة، العمل بعد تسجيل الخروج، الدوران التلقائي للسجلات، تجميع عمليات التطبيقات، SMART، تسجيل الحرارة والبطارية زمنيًا.
- خدمة systemd --user موثقة بوصفها الخيار المستقبلي، أما النسخة الحالية فتستخدم subprocess منزوع الارتباط بالطرفية لضمان نطاق أقل في أول تجربة.
- وضع `show` يعتمد على آخر عينة مسجلة ويحتاج مسجلًا نشطًا؛ لا توجد لقطة `--snapshot` مستقلة بعد.
- العملية لا تستطيع قراءة كل عمليات النظام في جميع الحالات؛ يذكر عدد عمليات الوصول المتعذر دون اعتبارها عمليات غير موجودة.
- `top --sort cpu` محكوم بما احتفظت به العينة من عمليات (أعلى RAM حتى الحد الافتراضي 300). هذا قيد معروف يجب إصلاحه لاحقًا.

## إثبات مبدئي
في بيئة Linux المتاحة للتطوير، نجحت تجربة بدء المسجل، ثم الاستعلام عن حالته وCPU والعمليات، ثم إيقافه وإعادة قراءة JSON المصدر. الاختبار لا يثبت توافق GPU أو systemd أو الحزمة على HP 630؛ ويجب تكراره ميدانيًا على Ubuntu 24.04.

## نتيجة الاختبار الميداني FT-001 — 28/10/2026

تمت مراجعة ملف JSONL فعلي كامل بـ129 عينة صالحة بين 19:45:49 و19:50:05 UTC، بفاصل متوسط قدره ثانيتان. نجح استعلام الحالة وعرض CPU والعمليات والذاكرة وإيقاف التسجيل وتصدير الجلسة. متوسط CPU للنظام 35.65%، ومتوسط حمل المسجل نفسه نحو 0.81% من كامل قدرات CPU المنطقية أثناء نشاط النظام، دون اختبار مرجعي يفصل كلفة SIM. لم تستخدم Swap، وGPU والطاقة غير مدعومين في العينات الحالية. حجم التصدير 4.91 MB في 4:16، ما يستدعي تدوير السجلات وتحديد الحجم قبل جلسات طويلة. **تفاصيل منهجية وقيود واضحة:** [FIELD_TEST_001.md](FIELD_TEST_001.md). لم تُرفع بيانات العمليات الخام إلى GitHub.

## نتيجة فحص العتاد FT-002 — 28/10/2026

اختُبر `sim doctor --json` بنجاح على الجهاز المرجعي، وقورنت أعداد الأنوية والذاكرة بمخرجات `lscpu` و`free -h`. البيانات: i3 M370، نواتان ماديتان/4 منطقية، 7.554 GiB RAM متاحة للنظام، Intel GPU `8086:0046`، kernel `7.0.0-38-generic`. تُظهر خريطة القدرات حرارة متاحة، لكن قيمتها لا تُسجل في عينات `Collector` حاليًا. تنقص تسمية Ubuntu الدقيقة في `doctor`، وGPU/Power لكل تطبيق وSMART غير منفذة؛ عدم كشف البطارية ليس إثباتًا لعدم وجودها. اكتمل جرد RAM عبر `dmidecode` في ملحق FT-002A: شريحتان DDR3 × 4 GB بسرعة 1067 MT/s، مع تأكيد Ubuntu 24.04.5 LTS من `/etc/os-release`، و`i915` كتعريف GPU مستخدم. ظهر `AC` وحده في مصادر الطاقة، ولا يثبت ذلك غياب البطارية ماديًا. [التفاصيل](FIELD_TEST_002.md).

## اختبارات القبول التالية
1. اكتمل تشغيل `sim doctor --json` والتحقق من وحدات RAM الفيزيائية واسم Ubuntu وتعريف GPU في FT-002A؛ يتبقى تحسين تمثيل هذه المعلومات آليًا داخل `doctor` وتفاصيل المستشعرات.
2. أُجري اختبار Brave أولي لمدة 4:16 ونجح التصدير؛ يُعاد الاختبار لمدة 30 دقيقة بعد تحسين سياسة حجم السجلات.
3. قياس CPU/RAM لمسجل SIM نفسه وتحديد مدى تأثيره على الجهاز القديم.
4. التحقق من صلاحيات الملفات وحجم الملف، وإجراء اختبار 30 دقيقة ثم 2 ساعة.
5. مقارنة القراءات بمعاني المؤشرات المقابلة لدى GNOME System Monitor وأدوات Linux.
