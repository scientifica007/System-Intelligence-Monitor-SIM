# ميثاق مشروع SIM — الهوية والأهداف

**الاسم الرسمي:** System Intelligence Monitor  
**الاسم المختصر:** SIM  
**التعريب الوصفي:** راصد ذكاء النظام  
**النوع:** مشروع برمجيات حرة ومفتوحة المصدر لمراقبة أداء Linux وتحليله  
**تاريخ اعتماد الميثاق الأولي:** 28/10/2026  
**صاحب المبادرة/المستودع:** scientifica007  
**حالة الوثيقة:** أساس مشروع، قابل للمراجعة الموثقة  
**الترخيص الأولي:** MIT

## 1. المشكلة
تعرض أدوات المراقبة المعتادة موارد النظام، لكن البيانات اللحظية وحدها لا تكفي لمعرفة ظروف اختناق الأداء أو إجراء مقارنة موضوعية قبل تعديل الإعدادات وبعده. غالبًا تتوزع البيانات عبر أدوات غير مترابطة ويصعب إعادة تحليلها آليًا.

## 2. الرؤية
أداة عامة تعمل أولًا على Ubuntu 24.04، ثم توزيعات Linux الأخرى، توحد القياس الزمني الموثوق والتوثيق والتحليل والتوصيات المدعومة بالأدلة، بحيث تصبح جلسة استخدام الحاسوب تجربة قابلة للاسترجاع والتحقق والمقارنة.

## 3. الأهداف الاستراتيجية
1. التقاط مؤشرات CPU وRAM وSwap والعمليات والقرص والشبكة، والمستشعرات المتاحة، مع إدراك حدود الوصول.
2. ربط العمليات بالتطبيقات مع تجنب العد المزدوج للذاكرة المشتركة والتباس معرّفات PID.
3. إتاحة تسجيل في الخلفية يتحكم به المستخدم من الطرفية: تشغيل/إيقاف/حالة/عرض/تصدير.
4. تخزين بيانات معرّفة بوحدات وطوابع زمنية ومصادر ودرجات إتاحة، بصيغ مفتوحة (SQLite وJSONL/JSON).
5. تقديم وصف إحصائي، ثم استدلال تشخيصي مقيّد، ثم توصيات قابلة للاختبار.
6. تقديم تطبيق سطح مكتب Ubuntu غني بالرسوم والتقارير دون ازدواج محرك القياس.
7. ترسيخ مشروع مفتوح المصدر قابل للمساهمة والاختبار عبر التوزيعات.
8. دعم مقارنة التطبيقات والإعدادات والتغييرات العتادية في تجارب متكررة.

## 4. الجمهور المستهدف
المستخدم التقني الذي يريد مراقبة مستمرة، ومطوّر البرمجيات الذي يريد تقييم تكلفة تطبيقه، والفني الذي يحلل بطء حاسوب، والباحث في قياس الأداء. لا يفترض استخدام سحابة أو اتصالًا دائمًا بالإنترنت.

## 5. النطاق
**في البداية:** Linux/Ubuntu 24.04، حاسوب مستخدم واحد، برنامج طرفية أصلي وخدمة تسجيل على مستوى جلسة المستخدم، ملفات محلية، قياسات مدعومة مباشرة أو معلنة عدم الإتاحة، تحليل وصفي وتقارير أساسية.

**لاحقًا:** سطح مكتب GTK، مقارنات A/B، كشف اختناقات، واجهات مستشعرات إضافية، توزيعات Linux أخرى، تحليل ذكي اختياري يمكن فصله عن القياس.

**خارج النطاق الابتدائي:** التحكم عن بعد، رصد لوحة المفاتيح، التقاط الشاشة، اعتراض اتصالات التطبيقات ومحتواها، مراقبة مستخدمين آخرين، إرسال قياسات تلقائيًا للخوادم، تغيير إعدادات حساسة دون إذن، أو تقديم قياس دقيق للواطات لكل تطبيق بلا جهاز قياس مناسب.

## 6. معيار المصداقية العلمية
كل مؤشر مرتبط بوحدة وطريقة قياس وفاصل زمني وصلاحية. كل استنتاج يميز بين «مقاس» و«مستنتج» و«مقدّر». الارتباط الزمني لا يثبت السببية؛ نحتاج مقارنة مضبوطة حين نريد إسناد سبب لنتيجة. أي مستشعر غير متاح يظل غير متاح ولا يُستعاض عنه بصفر.

## 7. مبادئ المنتج
- **محرك واحد لواجهتين:** CLI وDesktop عميلان لنواة مشتركة.
- **التشغيل الصريح:** لا تسجيل تلقائي إلا بإعداد اختياري واضح.
- **الأمان والخصوصية:** حفظ محلي وتدقيق البيانات قبل المشاركة.
- **الاستقلالية:** وظائف المراقبة الأساسية لا تحتاج ذكاء اصطناعي.
- **تدرج الدعم:** منصة Linux العامة هدف، وUbuntu أول اختبار.
- **الشفافية:** حدود البيانات والأخطاء والتحذيرات جزء من واجهة المستخدم.
- **الاستدامة:** لا نعتمد على واجهات خاصة بتوزيعة واحدة إلا عبر Adapter.

## 8. مخرجات النجاح
منتج قادر على تسجيل جلسة بقرار المستخدم، وإيقافها دون فقد البيانات المحفوظة، وإعادة قراءة الجلسة آليًا، وإظهار أعلى مستهلكي الموارد، ومقارنة سجلين، وإصدار تقرير يربط كل نتيجة بمؤشرها، مع مراقبة واضحة لاستهلاك SIM الذاتي.

## 9. الحدود والأخطار
قد لا يدعم العتاد القديم مقاييس GPU أو الطاقة؛ قد تختلف صلاحيات قراءة مؤشرات العمليات؛ بعض حسابات CPU تكون بالنواة المنطقية وبعضها بإجمالي الجهاز؛ قد تؤدي وتيرة الرصد العالية إلى تحميل إضافي على القرص والمعالج. هذه ليست أسبابًا لاختلاق القياسات بل حالات يجب التصريح بها.

## 10. سياسة التغيير
تُسجل القرارات التقنية المؤثرة في [DECISIONS.md](DECISIONS.md)، وتُحدّث المتطلبات والخطة عند تعديل نطاق المشروع. لا يتحول عنصر مخطط إلى «منفذ» قبل وجود شيفرة واختبارات ونتيجة تحقق موثقة.
