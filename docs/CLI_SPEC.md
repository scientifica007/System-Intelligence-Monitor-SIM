# مواصفة واجهة الطرفية — SIM CLI

**الحالة:** تصميم API مستقبلي؛ الأوامر أدناه غير منفذة في الوقت الحالي.  
**الأداة:** `sim`، تُتاح في PATH بعد تثبيت الحزمة مستقبلًا.

## 1. قواعد الاستخدام
- تشغيل التسجيل وإيقافه **بأمر صريح**؛ لا يشتغل تلقائيًا عند تثبيت التطبيق.
- التسجيل في الخلفية مستقـل عن جلسة shell/نافذة الطرفية، ضمن جلسة المستخدم الحالية.
- يستخدم Service Manager على Linux (مبدئيًا systemd --user) لإدارة المُسجّل؛ لا تعتمد المتانة على shell background أو PID file وحده.
- تفشل الأوامر بوضوح إذا كانت الجلسة بالفعل قيد التشغيل، ولا تنشئ جلستين متنافستين على التخزين.
- تعرض الأوامر النصوص المقروءة بشريًا افتراضيًا، و`--json` عندما يكون ذلك منطقيًا للاستهلاك الآلي.

## 2. أمثلة الأمر والعقد المستهدف
```bash
sim --help
sim version
sim doctor                       # جدول قدرات العتاد والمستشعرات والصلاحيات
sim doctor --json                # النتيجة نفسها للبرامج
sim start --interval 2 --label "Baseline"  # يبدأ المُسجّل بالخلفية
sim status                       # هل يعمل؟ الجلسة، PID إن وجد، المسار، الأخطاء
sim status --json
sim show cpu                     # أحدث عينة معروفة
sim show ram --json
sim show gpu                     # unavailability إذا لم يدعم العتاد
sim top --sort cpu --limit 15    # أعلى مستهلكي الموارد
sim top --sort ram --limit 10
sim live --refresh 2             # عرض يتحدث داخل الطرفية؛ Ctrl+C يغلق العرض فقط
sim sessions list                # جلسات التسجيل المسجلة
sim sessions show SESSION_ID
sim stop                         # يوقف المُسجّل ويحفظ نهاية الجلسة
sim export SESSION_ID --format jsonl --output ./session.jsonl
sim export SESSION_ID --format json --output ./session.json
sim analyze SESSION_ID --json
sim config show
```

## 3. حالات التشغيل
- **STOPPED:** لا مُسجّل قيد التشغيل؛ تبقى الجلسات القديمة قابلة للقراءة والتصدير.
- **STARTING:** يجري بدء الخدمة والتحقق من إنشاء سجل الجلسة.
- **RECORDING:** تعمل الخدمة وتسجل عينات وأحداث وفق السياسة.
- **STOPPING:** تطلب الخدمة التوقف، وتُفرغ المخازن وتغلق الجلسة.
- **FAILED:** فشل معروف يُعرض سببه وآخر وقت كتابة وموضع السجل إن وجد.
- `sim start` عند RECORDING لا يعيد بدء الخدمة أو يتلف الجلسة، بل يقدم خطأ مفهومًا أو يرشد إلى الجلسة الحالية.
- `sim stop` عند STOPPED آمن ولا يزيل البيانات، ويعلم المستخدم بعدم وجود تسجيل نشط.

## 4. العرض عندما لا يكون التسجيل نشطًا
أوامر `sessions` و`export` و`analyze` لا تحتاج تشغيل الخدمة. `show` و`top` يقرآن أحدث عينة عند وجود مُسجّل؛ وفي المستقبل يمكن `--snapshot` للحصول على قياس جديد غير مسجل، لكن ذلك يجب توثيقه بوضوح ولا يُعرض سجل قديم بوصفه مباشرًا.

## 5. المُسجّل في الخلفية
- مبدئيًا وحدة systemd user ومكوّن داخلي `sim-recorder`، مع IPC محلي محمي، وتجنب واجهة شبكية مفتوحة.
- تعيين فاصل افتراضي 2 ثانية للمقاييس الأساسية؛ يمكن أن يكون لكل مستشعر فاصل مختلف.
- **بعد تسجيل الخروج:** لا نَعِد باستمرار الخدمة تلقائيًا، لأن سلوك systemd user يعتمد على إعدادات جلسة المستخدم وlinger. دعم التشغيل عبر تسجيلات خروج متتابعة قرار لاحق يحتاج تحكمًا صريحًا.
- إيقاف الخدمة لا يعني حذف التسجيلات، ولا يشترط الرفع أو الاتصال بالإنترنت.

## 6. سلوك المخرجات والأخطاء
- عند طلب `--json` تُكتب بيانات JSON الصالحة إلى stdout، وتُرسل الرسائل التشخيصية إلى stderr.
- شفرة الخروج 0 للنجاح؛ أنواع الخطأ (معرّف جلسة غير موجود، صيغة تصدير غير مدعومة، نقص صلاحية، عدم إتاحة مستشعر، خطأ قاعدة بيانات) تُحدد وتختبر قبل استقرار الإصدار 0.1.
- CSV خيار إضافي للتجميعات والملخصات بعد ضمان تعبيره عن القيم المفقودة.
- لا يرسل الأمر `stop` إشارة قتل عمياء لكل عملية تحمل اسم sim؛ يتعامل مع معرّف الخدمة الموثوق.

## 7. مقياس الاستخدام الحقيقي
يمكن للمستخدم فتح الطرفية وتشغيل `sim start`، وإغلاق النافذة، ثم متابعة أعماله، وبعدها تشغيل `sim status` أو `sim top`، ثم `sim stop`، وأخيرًا تصدير الجلسة لتحليلها دون الحاجة إلى فتح تطبيق سطح المكتب.
