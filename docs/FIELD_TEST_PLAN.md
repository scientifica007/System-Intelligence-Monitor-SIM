# خطة الاختبار الميداني الأول — Ubuntu 24.04

**الغاية:** التحقق من دقة الرصد وكلفته ومتانة التسجيل، على الحاسوب الأول للمبادرة، ثم بناء سجل نتائج قابل لإعادة الفحص.  
**الحالة:** لم يُنفذ الاختبار؛ لا تُعد الصور السابقة نتائج اختبار SIM.

## 1. توصيف مرجعي أولي يحتاج تحققًا
حسب وصف المستخدم السابق: حاسوب HP 630 قديم، Intel Core i3 M370 ثنائي النواة وأربع خيوط، Ubuntu 24.04 LTS مع GNOME/Wayland، وقرص 500 GB تقريبًا. صورة System Monitor تعرض أربع وحدات CPU منطقية وذاكرة متاحة للنظام 8.1 GiB وقسمًا رئيسيًا 491.1 GB.

**اختلاف يجب فحصه لا افتراض سببه:** ورد سابقًا وجود شريحتي RAM بسعة 8 GB لكل منهما (16 GB مجموعًا)، بينما عرضت الصورة 8.1 GiB. لا نجزم بذاكرة مفقودة أو عطل من لقطة واحدة؛ نتحقق عبر `free -h` و`lshw` أو `dmidecode` عند الإذن، وقد تكون الصور لحاسوب أو وضع مختلف.

## 2. خطوات الاختبار
### FT-00: بيئة الأساس
تدوين تاريخ الاختبار، إصدار Ubuntu والنواة، الطاقة (بطارية/شاحن)، برامج الخلفية، نسخة SIM، التردد المختار، تهيئة الأجهزة. حفظ تقرير `sim doctor --json` بعد تنفيذه مستقبلًا.

### FT-01: صحة القراءة الأساسية
مقارنة عدادات CPU/RAM/Swap/القرص والشبكة بأدوات معروفة لدى Linux، مع بيان اختلاف نافذة الحساب ووحدات القياس؛ تُوثق أسباب فروق الأرقام بدل فرض تطابق حرفي.

### FT-02: إدارة التسجيل
بدء جلسة `sim start --interval 2`، ثم غلق الطرفية واستمرار العمل، والاستعلام من نافذة أخرى، وإيقاف الجلسة، ثم قراءة وتصدير السجلات. التحقق من الاستقرار بعد عدة تشغيلات متتابعة.

### FT-03: عبء المراقب
أخذ خط أساس من غير SIM ثم معه في خمول نسبي، وأثناء المتصفح، وأثناء ضغط مرتفع؛ قياس متوسط استهلاك CPU وRAM ومعدل الكتابة الذي يسببه SIM نفسه. العتبات في [REQUIREMENTS.md](REQUIREMENTS.md) أهداف مراجعة، لا نتائج مؤكدة.

### FT-04: الضغط والأخطاء
محاكاة اختفاء عملية أثناء أخذ العينة، انقطاع خدمة التسجيل، نقص الصلاحية، توقف مستشعر، نقص مساحة التخزين، تغير عدد العمليات، إعادة استخدام PID. يُفصل اختبار نفاد القرص عبر مساحة اختبار آمنة عن القرص الحقيقي الذي يحتوي بيانات المستخدم.

### FT-05: المتصفح
تسجيل جلسة Brave أثناء فتح صفحات وتشغيل وسائط وعمل اعتيادي، ثم إغلاقه. نتحقق من جمع العمليات تحت اسم تطبيق ومخاطر العد المزدوج للذاكرة. تكرار الاختبار عند المقارنة.

### FT-06: المتانة الزمنية
جلسات 10 دقائق و30 دقيقة وساعتين لاحقًا، مع تقدير حجم البيانات، وعدد العينات المفقودة، وسلامة JSONL والاستئناف بعد انقطاع متعمد.

### FT-07: المستشعرات الاختيارية
اختبار GPU/الطاقة/SMART/الحرارة حسب دعم الجهاز والتعريف؛ القيمة «غير متاحة» نتيجة اختبار صحيحة إذا أوضح النظام السبب، وليست فشلًا بحد ذاتها.

## 3. قالب نتيجة تجربة
| الحقل | المطلوب |
|---|---|
| Test ID / Date | معرّف وتاريخ بتنسيق dd/mm/yyyy |
| Host / kernel / SIM commit | الجهاز والنواة وإصدار الشيفرة |
| Scenario | سيناريو العمل وظروفه |
| Expected | التوقع قبل الاختبار |
| Observed | النتيجة والملفات والأرقام المقاسة |
| Status | PASS / FAIL / BLOCKED / NOT APPLICABLE |
| Limitation | مواطن الشك أو مستشعر غير متاح |
| Follow-up | مشكلة أو إجراء لاحق |

## 4. شروط قبول النسخة الأولية
- start/stop/status تعمل موثوقًا، وتُحفظ جلسة قابلة للتصدير.
- يمكن القراءة الآلية لسجلات الجلسة مع `schema_version`.
- كشف الفجوات وعدم إخفاء نقص المستشعرات.
- عدم ملاحظة تدهور غير مقبول في الجهاز المرجعي دون بيان السبب.
- تدوين كل فشل ومحدودية في تقرير اختبار، دون إعلان نجاح وظائف لم تُجرب.
