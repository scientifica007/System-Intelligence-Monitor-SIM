# خطة العمل المرحلية — SIM

**تاريخ التوثيق:** 28/10/2026  
**حالة المشروع:** التخطيط والتوثيق؛ لا شيفرة وظيفية بعد.  
**الترتيب:** النسخة الطرفية أولًا، ثم نسخة سطح المكتب، ثم التوسعة بين التوزيعات.  
**مبدأ التنفيذ:** لا نعلن نجاح مرحلة إلا عند استيفاء معيار قبولها وتوثيق تجربة المستخدم.

## المرحلة P0 — التأسيس واستكشاف القدرات
**المخرجات:** الميثاق والمتطلبات والمعمارية وعقد البيانات ومواصفة CLI (هذه الوثائق)؛ أداة استكشاف أجهزة/مستشعرات مستقبلًا؛ اختيار واجهات Linux المجدية.

**مهام التنفيذ التالية:** إعداد هيكل Python وpyproject، تحديد واجهات Collectors، تنفيذ `sim doctor`، رصد دعم المعالج والذاكرة والقرص والشبكة وGPU والطاقة، توثيق سبب غياب كل مستشعر.

**بوابة القبول:** جرد صحيح وقابل للتصدير JSON على Ubuntu 24.04، لا يدّعي أن ميزات غير مدعومة متاحة.

## المرحلة P1 — النواة وCLI المسجل
**المخرجات:** عملية جمع مستقلة، أوامر `start/stop/status/show/top/live`، مُسجّل خلفي ضمن المستخدم، مدير جلسات، دورة عينات متينة.

**الاختبارات:** تشغيل 30 دقيقة، غلق الطرفية واستمرار التسجيل في الجلسة، stop آمن، عدة مرات start/stop، التعامل مع انهيار مفاجئ، عدم وجود خدمة مخفية بعد إيقافها.

**بوابة القبول:** إتمام دورة تشغيل وتوقف بأوامر واضحة دون فقد الجلسة التي أُغلقت سليمًا.

## المرحلة P2 — البيانات والموثوقية
**المخرجات:** SQLite، تصدير JSONL/JSON، أحداث، بيانات النطاق، إصدار schema، التحقق، التحذير عند تضخم التخزين، تقدير عبء SIM نفسه.

**الاختبارات:** قراءة جلسة مجددًا، سلامة كل سطر JSONL، البيانات غير المتاحة، فصل process identity عند إعادة PID، استرداد سجل بعد انقطاع.

**بوابة القبول:** البيانات قابلة للتحليل ببرنامج مستقل وتعيد حساب الملخصات الصحيحة.

## المرحلة P3 — التحليل والتجارب
**المخرجات:** متوسطات/قمم/فترات الضغط، قواعد كشف اختناق أولية، مقارنة جلسات قبل/بعد، تقرير بأدلة وتوصيات محدودة الثقة.

**الاختبارات:** بيانات اصطناعية ذات نتيجة متوقعة، مقارنة الظروف المتشابهة، منع القفز إلى استنتاج سببي من مؤشر واحد.

**بوابة القبول:** لكل نتيجة رابط إلى مؤشر أو عينة، ولكل توصية تبرير ودرجة ثقة.

## المرحلة P4 — سطح المكتب Ubuntu
**المخرجات:** GTK4/Libadwaita، لوحة مراقبة، ترتيب التطبيقات، رسوم زمنية، تشغيل/إيقاف التسجيل، إدارة الجلسات، تصدير، دعم العربية RTL والإنجليزية، تغليف Ubuntu.

**الاختبارات:** استخدام فعلي على شاشة صغيرة 1366×768 وعلى Ubuntu 24.04 GNOME/Wayland، قابلية قراءة الرسوم، وضوح حالات غير متاح، عدم تضارب التحكم مع CLI.

**بوابة القبول:** نفس نتائج نواة القياس مع واجهة بصرية سليمة؛ حزمة قابلة للتثبيت والإزالة دون مسح بيانات المستخدم بلا إذنه.

## المرحلة P5 — التوسع في Linux
**المخرجات:** توثيق التبعيات، موائم مدير خدمات غير systemd عند الحاجة، تحزيم وتحقق Debian ثم توزيعات أخرى مثل Fedora.

**بوابة القبول:** كل توزيعة مستهدفة لها نتائج CI واختبار تثبيت وتشغيل، مع مصفوفة المزايا المتاحة وغير المتاحة.

## المرحلة P6 — ذكاء اختياري وتحسينات متقدمة
**المخرجات:** توصيات أغنى، تشخيص تاريخي، واجهات استيراد للتحليل، تحليل AI اختياري لا يُفعّل تلقائيًا ولا ينقل بيانات دون موافقة.

**بوابة القبول:** التوصيات قابلة للتتبع ولا تتجاوز قوة أدلتها، وتظل الوظائف الأساسية صالحة دون AI أو إنترنت.

## تسلسل الإنجاز القريب
1. تثبيت المواصفات والقرارات المفتوحة ومراجعتها.
2. تنفيذ اختبار `doctor` على العتاد المرجعي وتسجيل تقرير قدرات حقيقي.
3. بناء CLI محدود ب CPU/RAM/processes/disk/network وتسجيل JSONL.
4. تنفيذ دورة start/stop/status آمنة عبر systemd user.
5. اختبار استهلاك SIM والجلسات الكبيرة، ثم توسيع المستشعرات.
6. البدء في التحليل قبل الاستثمار الكبير في واجهة Desktop.

## سياسة الإصدارات
- `v0.1.0-alpha`: CLI أساسي بعد اجتياز اختبارات P1/P2 المناسبة.
- `v0.2.0-alpha`: تحليل ومقارنة مبدئيان بعد P3.
- `v0.3.0-beta`: Desktop Ubuntu بعد P4 واختبار المستخدم.
هذه **تسميات مقترحة وليست إصدارات موجودة أو مواعيد ملزمة**.

## إدارة المخاطر
أكبر المخاطر: GPU والطاقة في الأجهزة القديمة، تضخم حجم التسجيل، اختلاف معاني النسب، أثر SIM على جهاز محدود الأداء، اعتماد systemd، والصلاحيات. تُعالج بالتدرج، وكشف القدرات، وتخفيض الكلفة، والتوثيق الصريح.
